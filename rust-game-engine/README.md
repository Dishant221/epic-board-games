# epic-game-engine (Rust → WebAssembly)

Game rules and AI for Epic Board Games, compiled to Wasm with `wasm-pack`.

The TypeScript engine in `packages/game-core` is the **reference
implementation** and is what the site and the GameRoom Durable Object run
today. This crate is the high-performance twin: same rules, same AI, same RNG.

## Build

Requires stable Rust, the `wasm32-unknown-unknown` target and `wasm-pack`.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked

cd rust-game-engine
cargo test                      # native unit + integration tests
wasm-pack build --target web --release --out-dir ../apps/web/public/wasm/engine
```

The output (`epic_game_engine.js`, `epic_game_engine_bg.wasm`, `.d.ts`) lands in
`apps/web/public/wasm/engine/` and is served from `/wasm/engine/` by the static
assets. It is a build artifact — do not commit it. CI builds it on every run;
the deploy workflow builds it before `astro build` so it ships with the site.

```ts
import init, { GameBoard, TicTacToeAI, Connect4AI, AIDifficulty } from '/wasm/engine/epic_game_engine.js';
await init();
const board = new GameBoard(4, 0);      // 4 players, seed 0 = random
const roll = board.roll();              // 1..6
board.positions();                      // Uint8Array, 0 = start
board.lastJumpKind();                   // 0 none, 1 ladder, 2 snake, 3 croc, 4 dragon
new TicTacToeAI(AIDifficulty.Impossible).bestMove(Int8Array.from(cells), seed);
```

## Layout

```
src/
├── lib.rs                 # wasm-bindgen GameBoard (Snakes & Ladders)
├── utils.rs               # mulberry32 RNG (bit-identical to rng.ts)
├── games/
│   ├── snake_ladder.rs    # JUMPS table, exact-100, extra turn on 6, 3×6 forfeit
│   ├── tic_tac_toe.rs
│   └── connect4.rs        # rules + evaluate() heuristic
└── ai/
    ├── mod.rs             # AIDifficulty, AIPlayer (think delay, mistake rate)
    ├── minimax.rs         # generic negamax + alpha-beta, choose_move()
    ├── tic_tac_toe_ai.rs  # TicTacToeAI (perfect at Hard/Impossible)
    ├── connect4_ai.rs     # Connect4AI (centre-first ordering)
    └── snake_ladder_ai.rs # dice only — no decisions
tests/ai_tests.rs          # exhaustive TTT, C4 win/block, S&L rule cases
```

Planned (not yet implemented, intentionally no stubs): `chess_ai.rs`
(minimax + piece-square tables), `checkers_ai.rs`, `monopoly_ai.rs`
(heuristic buy/trade/build/mortgage), `mcts.rs`.

## Parity contract (TS ↔ Rust)

For the same inputs and seed, both engines must return the same result.

| Concern | TypeScript | Rust |
|---|---|---|
| RNG | `createRng(seed)` mulberry32, `int(min,max) = min + floor(next*(max-min+1))`, `pick = items[floor(next*len)]` | `utils::Rng` (same) |
| S&L jumps | `JUMPS` in `snakes-ladders.ts` | `JUMPS` in `snake_ladder.rs` |
| S&L roll | `rng.int(1, 6)` per roll | `GameBoard::roll` |
| AI mistake roll | `rng.next() < mistakeRate` (0.7 / 0.4 / 0.1 / 0) | `AIDifficulty::mistake_threshold` |
| AI depth | `DEPTH` in `ai/index.ts` | `depth_for` per game |
| Move order / ties | legal-move order, C4 stable centre-first sort; first strictly better score wins | same |
| C4 eval | `evaluateConnect4` | `connect4::evaluate` |
| Board encoding | TTT 9 cells; C4 42 cells at `col * 6 + row` (row 0 bottom); `-1` empty | same |

`utils::tests` pins reference outputs generated by `rng.ts`. If you change a
rule or constant on one side, change the other and update both test suites.
